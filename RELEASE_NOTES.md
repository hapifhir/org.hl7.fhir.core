## Validator Changes

* Server mode: new GET /canonical?url=[&version=] - the canonical resource (StructureDefinition, ValueSet, CodeSystem...) with that canonical URL, as the engine's context knows it (the core package, loaded IGs and their dependencies; nothing is fetched from elsewhere), or 404 with an OperationOutcome when it isn't known. The url must be absolute, and may carry a |version suffix instead of the version parameter
* Server mode: new -nonce option - the server returns the value in an X-Validator-Nonce header on every response, so a program that starts the server (e.g. fhir-validator-wrapper) can tell it from anything else answering on the port. Letters, digits, '.', '-' and '_', up to 128 characters; not a secret, and not authentication
* Command line: an old-style mode option after a command is an option of that command - `server 9096 -txTests` turns on the server's /txTest endpoints, instead of running the txTests command
* Terminology: global supplements - a supplement of type lang-pack or extension-codes (codesystem-supplement-type) that has codesystem-supplement-global = true is used whether or not it is referenced; any other supplement only when it is referenced. This replaces the global-lang-pack code from the last release: a supplement marked global-lang-pack, or lang-pack without codesystem-supplement-global, is now only used when referenced
* Terminology: reserved code spaces (codesystem-reservedCodeSpace) - a code that matches one is a valid code of the code system. Its display is the one an extension-codes supplement gives it (a global one first), else the code space's default-display ('User-assigned' if none). A different display is information when checked against the default, and a warning when checked against a display from a supplement that isn't global. A code from a reserved code space that a value set lists is in its expansion; an expansion of all of a code system that reserves code spaces is marked unclosed
* Terminology: merging supplements - a supplement's display for a concept is added as a designation in the supplement's language; nested concepts are merged once (they were merged once for each supplement, so their content was repeated); a supplement that is both global and named by the request is only merged once
* Terminology: only one version of a supplement applies - when several are in scope, the one asked for by version (useSupplement url|version), else the latest - and only that one is reported as used-supplement
* Terminology: `concept` / `code` `in` and `not-in` value set filters are supported in expansion and validation (`not-in` leaves out only the listed codes, not their descendants)
* Terminology: a code that a value set lists, but that is excluded because it is inactive (activeOnly, or compose.inactive = false), is reported as not in the value set, not as 'Code found in include, however'
* Terminology: the $expand `designation` parameter accepts a bare code (`designation=es`), which matches a designation's language or its use code from any system
* Terminology: batch validation of codes with no value set goes to CodeSystem/$batch-validate-code, as single codes go to CodeSystem/$validate-code (it went to ValueSet/$batch-validate-code with no url)
* Terminology: when a display matches a designation that has a standards status (e.g. deprecated), the alternatives offered are the designations in an acceptable language (the check looked at the wrong designation)
* Terminology: inferring the system of a code (code with no system, against a value set) when the value set includes a code system that isn't known is an error naming it (UNABLE_TO_INFER_CODESYSTEM_UNKNOWN_SYSTEM): the code might be in it. That include was skipped, and the system inferred from the others
* Terminology: expanding a value set whose include, exclude or filter has a modifier extension the expander doesn't know fails with VALUESET_MODIFIER_EXTENSION_UNKNOWN, naming the extension, as a problem with the value set (an OperationOutcome, not an exception). Modifier extensions on filters were ignored
* CodeSystem supplements: nested concepts are checked against the base code system, not just the top level ones; a warning when the supplement has no language (CodeSystem.language), so that its displays and designations with no language count as correct displays in all languages; in an extension-codes supplement, a warning for a code outside the base code system's reserved code spaces (it is treated as a code the code system defines), and for a code from a reserved code space that is nested in another concept or has concepts nested in it (no hierarchy is defined in reserved code spaces)

## Other code changes

* XmlEscaper (the IG publisher's escaped JSON includes): read as UTF-8 and write UTF-8 - characters other than ASCII were written as their low byte, which mangled everything above U+00FF and made even accented Latin characters invalid UTF-8; and write in blocks instead of a byte at a time, which was much slower on large IGs
* XhtmlParser: read runs of plain text, attribute values and names in one go (faster parsing; output and locations unchanged)
* Narrative: the CodeSystem "Additional Language Displays" table shows the displays for each language, not translated definitions; a language that only has translated definitions gets no column
* QuestionnaireBuilder: the answer constraint for a coded item was inverted - a required binding now gives optionsOnly, and any weaker binding optionsOrType
* NPM package generation: getRenamedFiles() reports the files whose path was too long for a tar entry and so are in the package under a shortened name
* R5 -> R6 conversion: read the Requirements.actor key also from the tools extension `requirements-actorkey`, as written by older IG Publisher versions (HL7/fhir-ig-publisher#1449)
