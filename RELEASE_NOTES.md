## Validator Changes

* When several versions of an extension definition are in scope, validate against the most recent one rather than the version a profile's dependencies bring in (logged when they differ)
* Whitespace: leading/trailing whitespace is only reported for the characters XML treats as whitespace (tab, space, CR, LF); a value that contains only whitespace now counts as a value (not empty) in all versions, and gets new hint/warning messages that depend on whether the resource is (or may be) represented in XML/RDF
* Terminology content in both hl7.terminology and a FHIR core package (CanonicalResourceManager): THO's copy is still what a reference with no version gets, but the core versions are no longer dropped - a reference that names a core version (url|5.0.0, or url|5.0) gets it, unless THO provides that version itself. Previously such references failed, including THO's own value sets that pin a core version (ValueSet/concept-property-type 6.0.1 includes concept-property-type 5.0.0). A core resource loaded after THO no longer becomes the default for the url when its (pre-THO) version is higher
* The terminology ecosystem coordination server (tx-reg) is now independent of the terminology server: by default it is https://ecosystem.hl7.org/tx-reg (configurable as txEcosystem in fhir-settings.json), and the new -ecosystem parameter nominates a different one ('n/a' for none). As before, nominating a terminology server with -tx turns the ecosystem off unless -ecosystem is given too, and -tx n/a turns both off. The same rule now applies to library callers and to the validator wrapper (ValidationEngineParameters, ValidationEngineBuilder, connectToTSServer): a terminology server other than the default means no ecosystem unless one is given explicitly, so that requests meant for a private server aren't routed on to other servers
* Removed the -check-ips-codes option (and the 'Snomed CT code is not a member of the IPS free set' check). checkIPSCodes is still accepted, and ignored, in server mode requests
* Terminology: a ValueSet include with no system (one that only imports value sets) is always used when choosing which includes apply to a code system version (#2775, #2769)
* Terminology: fix supplements that name a code system without a version - they apply to every version of it
* Terminology: recognise the notSelectable property by its standard uri whatever code the code system gives it (a code declared with a different uri is a different property), and make the notSelectable/abstract check much faster
* Terminology: recognise global-lang-pack as well as lang-pack code system supplements
* Extensible binding messages now say a code SHALL come from the value set unless it has no suitable code (was 'should')
* A constraint on a type slicer (binding, maxLength, minValue etc.) that only makes sense for some of its types is a warning when it is in the differential, and a hint when it only appears in the snapshot
* QuestionnaireResponse.item.text may match a translation (translation extension) of the Questionnaire.item.text, not only the text itself
* A meta.profile repetition with no value (e.g. only a data-absent-reason extension) is a warning that it claims no profile, instead of an NPE (#2767)
* Validating a StructureDefinition with no baseDefinition or derivation no longer crashes (logical models), and any StructureDefinition other than Base (and the R4 roots Element and Resource) must have both (SD_MUST_HAVE_BASE_AND_DERIVATION) (#2770)
* contentReferenceProfile: applied after snapshot expansion; a value must have a canonical before the '#'; a value that can't be resolved (no '#', unknown profile, unknown element id) is reported as an error on the instance element instead of stopping validation, and is checked once when validating the StructureDefinition itself; fixes for alternative profiles, reference cycles and shared invariants (reported once)
* Snapshot generation: a derived profile can reslice an inherited slice and then constrain a later inherited sibling slice - this failed with 'Named items are out of order in the slice', or put the new reslice after the sibling

* FHIRPath conformsTo() in the validator can name an implementation guide - by url or package id, optionally versioned - as well as a profile (an extension to the FHIR definition): the resource conforms unless it fails one of the profiles the IG (or its dependencies) makes apply to it - its global profiles for the resource's type, and the profiles whose rules about the resource's code (code, vaccineCode or medication: a fixed or pattern value, a required slice on code.coding, or a required binding) the resource's code meets
* FHIRPath: implement the document functions section(), entry(), entryIn(), resources(), resourcesIn() and sameSubject() (local extensions, R4, R4B, R5 and R6) - for rules about what a document (e.g. an IPS) contains. Tests are in the fhirpath test suites, in a group marked mode="custom". In a document, section entries are resolved the way the validator resolves references in a Bundle, and only in the document
* FHIRPath: new document function hasCoding(system, code [, version]) (a local extension, R4, R4B, R5 and R6): on Codings or CodeableConcepts, whether any coding has that system and code (and version, when one is given); empty when the input is empty
* FHIRPath (all versions): fixes from running the FHIRPath spec test suite edge cases - substring() returns '' for a zero or negative length, treats an empty length as no length, and no longer throws on a negative length or an empty start; skip() and take() return empty for an empty count, and skip() with a negative count or index and division by zero give the spec results; ordering operators on quantities give empty when the units can't be compared; comparing dateTimes no longer changes the values compared, and minute-precision dateTime literals compare and copy correctly; unescape('json') handles quotes and unicode escapes; invalid \u escapes are a lexer error, and escapes in delimited identifiers are read as in strings
* FHIRPath: guard against deeply nested/recursive expressions (parse depth limit), and give informative errors for malformed expressions (e.g. an unterminated string) instead of index exceptions
* Server mode: new GET (or POST) /fhirpath/check?type=&expression= - static type checking of a FHIRPath expression against the type it is evaluated on (a type name, a path in one, or a StructureDefinition URL), without evaluating it. Returns an OperationOutcome: an error when the expression doesn't parse (with line and column) or doesn't check, the checker's warnings (with message ids), and when there's no error, the type the expression returns
* The terminology tests report the version of the test package they ran (it was always 1.9.3, read from the frozen tests/history.json)
* Server mode terminology tests: new POST /txTest/setup and POST /txTest/teardown bracket a run of GET /txTest calls. Setup fixes the server, the test-version (no longer always the dev package), the externals (as content, not a package file name), the output folder and the tester; the FHIR version comes from the server. Teardown returns (and writes) test-results.json and report.json, as the command line does. Tests that don't run - now including disabled tests and FHIR version gated tests - return an error but aren't counted. The default modes no longer include tx.fhir.org (or closure, which is a feature now), and now include loinc and icf. The old server= form still works
* Server mode: the /txTest endpoints are now off unless the server is started with -txTests - they are for build pipelines, and connect to a caller-named server and write output files on the host. When the server isn't bound to loopback, /txTest only tests servers configured in fhir-settings (403 otherwise). Teardown of a session is now atomic. Documented what a /txTest client is expected to do
* Terminology tests: each run uses its own closure table (a fresh UUID), so concurrent runs against one server don't interfere
* Server mode: query parameters were decoded twice (e.g. a '+' or '%' in an expression or url was corrupted); tightened status codes - an invalid FHIRPath expression on /fhirpath is a 200 with an OperationOutcome, an unknown map is a 400, and parse/check failures on /fhirpath/check are reported in the OperationOutcome
* VCL: limit the nesting depth of VCL expressions, with an error naming the expression

## Other code changes

* Narrative: a Reference with the alternate-reference extension (target type not allowed by the element) links to the target in the extension, also when it has a display or identifier, instead of ?rref? or plain text (HL7/fhir-ig-publisher#1423)
* Consent renderer (R4/R4B): use the R5 decision modifierExtension (http://hl7.org/fhir/5.0/StructureDefinition/extension-Consent.decision) as the base rule, and render a provision without type (the root rule) with the permit/deny of its parent instead of deny (HL7/fhir-ig-publisher#1422)
* Fix R4/R4B to R6 conversion of Immunization.protocolApplied.doseNumber[x] and seriesDoses[x]: keep the original positiveInt type and the primitive's extensions, e.g. a data absent reason on a value-less dose number (HL7/fhir-ig-publisher#1362)
* Narrative: contentReferenceProfile values without a canonical are rendered as invalid references instead of linking into the profile
* Narrative: CodeSystem property links were inverted - only properties with the no-link display hint now skip the link; new rendering option to suppress the CodeSystem properties table (RenderingContext csProperties)
* Narrative: empty auto-created children no longer count as slicer rules, so the slicer rules display doesn't depend on what was rendered before
* Narrative: Provenance renders anchors for contained resources, so links to them resolve
* Narrative: accessibility changes - use CSS classes rather than inline styles (e.g. unchanged/removed content in comparisons), and markdown is rendered with URL sanitisation
* LanguageUtils: look for an exact language match in narrative divs before a near match
* Translations of a text are kept in the order they are listed (were in random order each build)
* NPM package generation: file names too long for a tar entry are shortened with a hash, and the length check now counts UTF-8 bytes (it was off by one)
* ValueSetExpansionOutcome constructors accept a null error list (#2768)
* CanonicalResourceManager: has() and get() now agree (has() could say true when get() found nothing, or vice versa); THO packages detected by isTHO()
* Primitive types (all versions): hasValue()/isEmpty() treat a whitespace-only value as a value
* R6: regenerate the IG based content, and restore the hand-written StructureMap code lost in regeneration
* Add 'fhir-pd' (FHIR Product Director) as a known committee/work group code
* Upgrade pubpack to 0.2.12
* Build: SpotBugs report and README documentation (thresholds overridable from the command line); faster CI test jobs; fix the cli module timeout
