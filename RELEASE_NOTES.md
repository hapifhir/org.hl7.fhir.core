## Validator Changes

* Terminology: a value set that requires a code system supplement (the valueset-supplement extension) is sent to a server that knows the supplement. When a server is chosen, the supplements a value set requires count as code systems the server must support, so a server that is authoritative for the code system but doesn't have the supplement is no longer chosen (a Canadian value set on v3 ActCode that requires the Infoway fr-CA supplement went to tx.fhir.org instead of the Canadian server). Validating locally, a required supplement that isn't loaded, but that the terminology ecosystem knows a server for, sends the validation to that server; a supplement no server has is still reported as missing (TerminologyClientManager.isKnownToEcosystem)

## Other code changes

* PathBuilder (Windows): [tmp] is no longer c:\temp when file access is limited (ManagedFileAccess.setAllowedPaths) and c:\temp isn't one of the allowed folders - e.g. it didn't exist when the IG publisher set its limits, so [tmp] was somewhere else then. Files in it were refused ('cannot be accessed by policy'). ManagedFileAccess.inAllowedPaths() is now public
* XSLT (#2902): XsltUtilities and its URI resolvers move to org.hl7.fhir.utilities.xslt (XsltUtilities, XsltURIResolver, XsltZipURIResolver). The old classes (org.hl7.fhir.utilities.XsltUtilities, MyURIResolver, ZipURIResolver) are kept as deprecated wrappers, and will be removed. A transform's includes, imports and document() calls can only read files inside its folder - an absolute path elsewhere, a .. that leads out, or a symbolic link that leads out is refused. An http(s) url is only resolved by a resolver the caller supplies: nothing is fetched otherwise (it used to be fetched). The documents being transformed are read without external DTDs or entities (XXE). Utilities.forcePath (unused) is removed
* org.hl7.fhir.support: the utility and tooling classes that the validator and the IG publisher don't use - analysis tools, the ADL and CKM importers, package building and maintenance tools, resource patch-up tools, the batch loaders, DigitalSignatures, the CPT, CVX and other terminology importers, Unbundler, ParametersBuilder, PackageValidator and others - move there from convertors (misc), r4, r4b and r5 (utils), utilities (npm) and validation, in packages under org.hl7.fhir.support. The main() methods of ToolsHelper (r4, r4b, r5) and CsvFormat are removed
